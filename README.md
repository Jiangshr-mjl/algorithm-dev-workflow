# algorithm-dev-workflow

面向多轮算法开发的 AI 协作 skill：让每次修改的目的、代码变化、运行证据和下一步都有据可查，由 AI 维护项目状态和尝试记录。

算法和数据处理口径的实质变化先审查、再运行；用户明确要求的简单调整直接完成并验证；纯咨询只解释。

## 适用场景

- 连续进行算法或科研代码迭代，需要知道每次改动与结果的对应关系。
- 在运行实验前，希望先理解核心逻辑、改动范围与待验证点。
- 切换对话后，需要凭项目内的状态和记录接着工作。
- 代码、输出和临时文件逐渐混乱，需要先梳理现状再决定下一步。

## 协作方式

| 你的请求 | AI 的处理方式 |
| --- | --- |
| 咨询或解释 | 只读理解并回答，不修改文件、不创建记录、不运行代码 |
| 启用流程 | 在指定项目中创建或合并协作约定、状态文件和尝试模板 |
| 简单调整 | 在已授权范围内修改并进行必要验证，记录改动和结果 |
| 算法或数据处理的实质变化 | 保留基线，修改并说明核心逻辑，等待审查和运行授权 |
| 继续或恢复任务 | 先读取状态与关联记录，对照实际文件说明当前位置 |
| “现在太乱了” | 暂停新增修改和实验，梳理已确定内容、未决问题和下一步选项 |

简单调整包括绘图布局、配色、字体、标签、图例、输出格式，以及不改变计算含义的局部修正。是否属于简单调整取决于实际影响，而不是改动行数；改变数据筛选、插值、积分口径、统计样本或指标定义时，需要按实质变化处理。

## 安装

获取本仓库：

```bash
git clone https://github.com/Jiangshr-mjl/algorithm-dev-workflow.git
```

将整个 `algorithm-dev-workflow` 文件夹放入所用 AI 工具支持的 skill 目录，保留 `SKILL.md` 与 `assets/` 的相对位置。具体安装位置与加载方式以客户端的 skill 配置为准。

安装目录用于保存可复用的 skill；启用流程时，请另外指定实际算法项目的位置。

## 快速开始

在能够加载此 skill 的 AI 工具中，可以使用以下请求。将示例中的项目路径和任务描述换成自己的实际内容。

### 1. 在项目中启用

```text
请使用 algorithm-dev-workflow，在 <项目路径> 启用算法开发协作流程。
先阅读已有项目约定，合并必要文件，说明创建或合并了什么。
这次只初始化，不修改算法或运行实验。
```

初始化会按实际情况创建或合并 `AGENTS.md`、`DEV_STATE.md` 和 `experiments/TEMPLATE.md`。已有规则、状态与历史记录会被保留；未知信息明确标注，不创建虚假尝试。

### 2. 开始一次算法修改

```text
请按 algorithm-dev-workflow 调整 <具体算法逻辑>，目的是 <预期解决的问题>。
先保留修改前基线。修改后解释核心逻辑、相关文件和验证方案，等我审查后再运行。
```

每次围绕一个明确目的创建 `EXP-0001` 形式的尝试记录。同一目的下的审查修订沿用编号，保留最初基线；新的优化目的另行处理。

### 3. 完成一个简单调整

```text
请将 <绘图文件> 的图例移到图外，增大坐标轴字体，并运行必要验证。
保持计算逻辑和数据口径不变，记录本次改动及新输出位置。
```

已明确授权的同范围简单调整可直接完成并验证，不需要机械地重复确认。用户明确要求先审查或禁止运行时，仍遵从该要求。

### 4. 在新对话中接续

```text
请先阅读 <项目路径> 的 AGENTS.md、DEV_STATE.md 和相关尝试记录，
对照实际文件，向我解释现在做到哪里、还有什么未确定、下一步有哪些选择。
暂时不要修改或运行。
```

跨对话接续依靠项目内保存的约定和记录；新对话需要读取这些文件，不假定所有对话都会自动加载此 skill。

## 仓库内容

| 文件 | 用途 |
| --- | --- |
| [SKILL.md](SKILL.md) | skill 的完整行为规则与处理流程 |
| [assets/AGENTS.md](assets/AGENTS.md) | 合并到目标项目的 AI 协作约定模板 |
| [assets/DEV_STATE.md](assets/DEV_STATE.md) | 当前目标、代码状态、阶段、结论和下一步的模板 |
| [assets/EXPERIMENT.md](assets/EXPERIMENT.md) | 单次尝试的目的、基线、修改、审查、运行与结论模板 |

目标项目中的典型结构如下；尝试记录、备份和输出目录只在实际需要时创建：

```text
your-project/
├── AGENTS.md
├── DEV_STATE.md
└── experiments/
    ├── TEMPLATE.md
    ├── EXP-0001.md
    ├── baselines/
    │   └── EXP-0001/
    └── outputs/
        └── EXP-0001/
            ├── run-001/
            └── run-002/
```

项目已有合适的文件组织约定时沿用，并在记录中注明实际位置。

## 记录与验证原则

- **可恢复**：有有效 Git 时记录提交及工作区状态，对未提交内容额外保留副本；否则备份将修改的已有文件。此流程本身不自动初始化或提交 Git。
- **可追溯**：关联代码状态、实际命令、工作目录、关键参数、数据版本、结果位置与指标。建议命令和实际执行命令分开记录。
- **如实记录**：未执行写“未运行”，效果写“未验证”；失败和中断也保留，不把运行成功等同于效果提升。
- **保留历史**：多次运行使用不同输出目录，同一尝试的审查修订不覆盖修改前基线。
- **尊重授权范围**：已有明确运行授权时按其范围执行；实质变化或运行范围扩大后，重新审查并取得对应许可。

这是一套由 AI 执行的协作约定，不是自动实验平台或强制权限控制系统。建议先完成两次真实尝试，检查追问时文件是否稳定、运行前是否理解改动、结果能否关联代码和命令，以及新对话能否凭记录继续，再调整记录粒度。
